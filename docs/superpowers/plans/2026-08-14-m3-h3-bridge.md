# M3 H3 Bridge (Vertical Slice) Implementation Plan (Final)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove one real end-to-end generation path: existing canonical ShotSpecificationV1 + GenerationPlan → H3PromptV1 → parameterized H3 R2V workflow → ComfyUI REST/WebSocket execution → generated video retrieved → Take 1 persisted → last frame extracted with FFmpeg.

**Architecture:** M3 adds the first provider-specific layer BELOW the model-agnostic M2 boundary. An immutable `H3ReferenceBinding` list (with content SHA-256) is the SINGLE AUTHORITATIVE source for prompt rendering, reference upload, workflow slot injection, and execution snapshot — ensuring ordering consistency and exact reproducibility. H3PromptBuilder deterministically assembles prompt text. WorkflowRegistry resolves strategy to a versioned+fingerprinted workflow template. A single authoritative set of `WorkflowInjection` records drives BOTH workflow JSON mutation and `GenerationRequest.parameters_snapshot` — what is persisted IS what is submitted. GenerationRequest is INSERT-ONLY (immutable inputs). Media staging ensures Takes never point to missing files. Take insertion + request-succeeded status are committed in ONE short SQLite transaction.

**Tech Stack:** Python 3.14.3, FastAPI, Pydantic v2, SQLite, httpx (ComfyUI REST), websockets (ComfyUI WS), subprocess/FFmpeg, pytest

## H3ReferenceBinding — Frozen Immutable Binding

```python
@dataclass(frozen=True)
class H3ReferenceBinding:
    """One subject→reference slot binding. FROZEN — never mutated in place."""
    subject_index: int          # 1-based: <Subject N>
    character_id: str
    character_name: str
    appearance: str             # from CharacterReference.appearance
    picture_index: int          # 1-based: <Picture N>
    local_path: str             # resolved filesystem path
    content_sha256: str         # SHA-256 of local file bytes (exact identity)
    uploaded_filename: str = "" # empty until upload creates NEW binding via replace()
```

**Immutable transition flow:**
```
H3ReferenceResolver
  → resolved_bindings: list[H3ReferenceBinding]   (uploaded_filename="")
  ↓
H3PromptBuilder uses resolved_bindings for <Subject N>/<Picture N>
  ↓
ComfyUI uploads in resolved_bindings order
  ↓
uploaded_bindings = [dataclasses.replace(b, uploaded_filename=name) for b, name in zip(resolved_bindings, uploaded_names)]
  ↓
ParameterResolver uses uploaded_bindings for workflow slot injection
  ↓
GenerationRequest.reference_snapshot built from uploaded_bindings
```

**NEVER mutate a binding in place.** Upload creates a NEW list with `dataclasses.replace()`. Both lists preserve identical ordering and indexes.

## H3ReferenceResolver — Minimal M3 Resolver

```python
class H3ReferenceResolver:
    def resolve(self, shot: ShotSpecificationV1, characters: list[CharacterReference],
                max_refs: int) -> list[H3ReferenceBinding]:
```

Rules:
1. For each ShotSubject in `shot.subjects` order (stable):
   - Find matching `CharacterReference` by `subject.character_id`
   - Require at least one path in `subject.ref_images`
   - Select FIRST `ref_images` path
   - Verify file exists locally
   - Compute SHA-256 of file bytes
   - Create frozen `H3ReferenceBinding`
2. If any subject has no match, no path, or file missing → `ReferenceResolutionError`
3. If `len(bindings) > max_refs` → `ReferenceResolutionError`
4. NOT M5: no ranking, face detection, scene refs, style refs, embeddings

## WorkflowInjection — Authoritative Injection Record

```python
@dataclass(frozen=True)
class WorkflowInjection:
    """One concrete parameter injection. Drives BOTH workflow JSON mutation AND parameters_snapshot."""
    name: str           # semantic name: "prompt", "seed", "ref_image_0", etc.
    node_id: str        # actual workflow node ID
    field: str          # actual field name within the node
    value: str | int | float  # actual concrete submitted value
```

**Single-source invariant:** ONE list of `WorkflowInjection` records is built by ParameterResolver. That SAME list:
1. Drives workflow JSON mutation (each injection applied to template copy)
2. Becomes `GenerationRequest.parameters_snapshot` (serialized as-is)

What is persisted IS what is submitted. No second mapping pass.

## WorkflowDefinition — Versioned + Fingerprinted

```python
@dataclass(frozen=True)
class WorkflowDefinition:
    id: str
    version: str                      # human-readable, e.g., "1.0.0"
    strategy: str
    template_path: str
    template_fingerprint: str         # SHA-256 of template file content
```


## Generation Orchestration Order (CORRECTED)

```
1.  Load current ShotSpecificationV1
2.  Load current GenerationPlan (must be REFERENCE_TO_VIDEO, version matched)
3.  Resolve CharacterReferences for subjects
4.  H3ReferenceResolver → resolved_bindings (with content_sha256)
5.  Validate: len(bindings) <= workflow max_reference_images
6.  Build/reuse current H3PromptV1 (using resolved_bindings)
7.  Resolve WorkflowDefinition
8.  Load workflow template + verify fingerprint
9.  Upload references in binding order → uploaded_bindings (new frozen list)
10. Resolve concrete seed
11. Resolve concrete duration/frame + aspect parameters
12. ParameterResolver builds ONE authoritative list[WorkflowInjection]
13. Apply injections to template copy → submission-ready workflow JSON
14. Validate resulting API workflow (all mapped nodes/fields exist)
--- FAILURE BEFORE THIS POINT: NO GenerationRequest ---
15. CREATE GenerationRequest (persist — INSERT-ONLY, with parameters_snapshot + reference_snapshot)
16. POST /prompt to ComfyUI (update request with comfyui_prompt_id)
--- FAILURE AFTER THIS POINT: request persisted, status → failed ---
17. Monitor via WebSocket until complete/failed
18. Get result → download to staging
19. Verify media + FFmpeg last frame → staging
20. Move staging → final Take directory
21. SHORT SQLite transaction: insert Take + update GenerationRequest → succeeded
22. If Take insert or DB commit fails: request status remains non-succeeded
```

**No SQLite write transaction during ComfyUI wait (steps 17-19).**

## Failure Boundary

**BEFORE GenerationRequest creation (steps 1-14) — NO request persisted:**
- UnsupportedStrategyError, missing/stale Shot/Plan, ReferenceResolutionError, reference file hashing failure, H3Prompt build failure, WorkflowTemplateError, fingerprint mismatch, reference upload failure, ParameterResolutionError, workflow injection failure, submission-payload validation failure

**AFTER GenerationRequest creation (steps 15+) — request persisted:**
- POST /prompt failure, WebSocket failure, ComfyUI execution error, result retrieval failure, media download failure, media verification failure, FFmpeg failure, staging finalization failure, Take insert failure
- All → GenerationRequest retained with status=failed + error details

**Finalization atomicity:** Step 21 is ONE short SQLite transaction. If it fails, media may exist on disk but no succeeded request or Take record exists. Orphaned staging files are acceptable for M3 (documented cleanup policy).
